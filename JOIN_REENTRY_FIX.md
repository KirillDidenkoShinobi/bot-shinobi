# Повторные заявки

- Каждое новое событие заявки Telegram (новая дата event.date) создаёт новую карточку даже для того же пользователя.
- Повторное получение того же события не создаёт карточку.
- Предыдущая карточка остаётся в истории и не управляет новой заявкой: callback содержит ID цикла.
- Таймер автоматического принятия старой заявки не принимает новую.
- История предыдущих заявок: join_request_history в данных бота.
- Для старых заявок без event_stamp используется время создания как резервный ориентир.
- Telegram передаёт дату события с точностью до секунды: если пользователь отменил и подал заявку повторно в ту же секунду, события могут быть неразличимы.
- Не заменяйте production базу данными из ZIP.
- Проверен синтаксис, не проверена живая доставка в Telegram.
