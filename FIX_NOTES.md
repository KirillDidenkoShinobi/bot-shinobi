# Shinobi links and delivery fixes

- Старый рекламный URL в архиве недействителен. Бот не может восстановить отозванную ссылку: в **Админ-панель → Рекламная ссылка → Создать новую рабочую ссылку** бот создаёт новую ссылку с заявками. Скопируй её для рекламы. Для этого у бота должно быть право приглашать пользователей.
- Ссылка теперь сохраняется в `data.json` и не перезаписывается старой константой при перезапуске. История старой ссылки и её 189 приглашений сохраняется отдельно, новая начинает с 0.
- `SHINOBI_ADMIN_IDS` в Railway Variables: числовые ID дополнительных администраторов через запятую. Пользователи должны хотя бы раз нажать Start в ЛС бота, иначе Telegram запретит писать им первым.
- `/delivery_test` в ЛС боту от владельца проверяет доставку в Staff и всем указанным администраторам, возвращает конкретные ошибки Telegram.
- Ошибки доставки карточек заявок теперь видны в логах Railway и записываются в `data.json` внутри заявки (`delivery_errors`).
- В меню «Тех. работы» показывается фактическое количество успешных и неуспешных доставок.
- Для заявок бот должен быть администратором основной группы и иметь право приглашать пользователей. Для отправки в Staff бот должен быть участником Staff с правом отправки сообщений.
- **Не меняй/не удаляй существующую базу данных Railway**. После деплоя сохранённая база восстановится и новая ссылка будет записана поверх только при её явном создании.
- Проверены синтаксис Python и ZIP; живые Telegram-отправки без токена не тестировались.
